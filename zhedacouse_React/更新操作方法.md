## 当前构建规则

- 当前仓库通过 `gh-pages` 发布到 GitHub Pages
- GitHub Pages 绑定了自定义域名 `zju.yolodeep.fun`
- 因为最终访问地址不带仓库名前缀，所以生产构建统一使用根路径 `/`
- `npm run deploy` 会先执行 `npm run build`，然后将 `dist` 发布到 `gh-pages` 分支

## 首次部署

1. 确认代码已经推送到 GitHub 主分支。

```bash
git add .
git commit -m "chore: prepare github pages deploy"
git push origin main
```

2. 在项目根目录执行部署命令。

```bash
npm run deploy
```

3. 打开 GitHub 仓库设置。
4. 进入 `Settings` -> `Pages`。
5. 在 `Source` 中选择 `Deploy from a branch`。
6. 分支选择 `gh-pages`，目录选择 `/(root)`。
7. 保存后等待 1-3 分钟。

## 后续更新

代码改完后，按下面步骤更新线上页面：

```bash
git add .
git commit -m "feat: 你的更新说明"
git push origin main
npm run deploy
```

部署完成后，等待约 1 分钟，刷新站点即可看到最新内容。

## 常见问题

### 页面 404

- 检查 GitHub Pages 是否已经切到 `gh-pages` 分支
- 检查仓库 `Settings -> Pages` 中的 Custom domain 是否为 `zju.yolodeep.fun`
- 如果是访问子路由时报错，先重新执行一次 `npm run deploy`

### 自定义域名白屏

- 如果控制台里资源请求还是 `/zhedacouse/assets/...`，说明线上仍然是旧版构建产物或缓存未刷新
- 重新执行一次 `npm run deploy`
- 到 GitHub Pages 设置页确认自定义域名已生效，并等待缓存刷新

### 图片不显示

- 新增图片时，优先放到 `public` 目录
- 代码里不要手写以站点根目录开头的绝对路径，保持走现有的 `withBasePath()`

### 页面改了但线上没更新

- 先确认本地执行过 `npm run deploy`
- 再确认部署命令执行过程中没有报错
- GitHub Pages 可能有 1-3 分钟缓存，稍等后强刷页面再看
