## 双环境构建说明

- `npm run build`：构建自定义域名版本，资源路径为根路径 `/`
- `npm run build:github-pages`：构建 GitHub Pages 版本，资源路径为 `/zhedacouse/`
- `npm run deploy`：自动执行 GitHub Pages 版本构建并发布到 `gh-pages` 分支

## 首次部署

1. 确认代码已经推送到 GitHub 主分支。

```bash
git add .
git commit -m "chore: prepare github pages deploy"
git push origin main
```

2. 在项目根目录执行部署命令。

```bash
npm run deploy
```

3. 打开 GitHub 仓库设置。
4. 进入 `Settings` -> `Pages`。
5. 在 `Source` 中选择 `Deploy from a branch`。
6. 分支选择 `gh-pages`，目录选择 `/(root)`。
7. 保存后等待 1-3 分钟。

## 后续更新

代码改完后，按下面步骤更新 GitHub Pages 页面：

```bash
git add .
git commit -m "feat: 你的更新说明"
git push origin main
npm run deploy
```

部署完成后，等待约 1 分钟，刷新站点即可看到最新内容。

## 自定义域名发布

如果你要发布到 `https://zju.yolodeep.fun/` 这类自定义域名，使用默认构建即可：

```bash
npm run build
```

然后把 `dist` 目录内容上传到你的服务器或静态托管平台。

## 常见问题

### 页面 404

- 检查 GitHub Pages 是否已经切到 `gh-pages` 分支
- 检查访问地址是否为 `https://hyyyy051028.github.io/zhedacouse/`
- 如果是访问子路由时报错，先重新执行一次 `npm run deploy`

### 自定义域名白屏

- 如果控制台里资源请求还是 `/zhedacouse/assets/...`，说明你用了 GitHub Pages 构建产物去部署自定义域名
- 自定义域名必须使用 `npm run build` 生成的产物
- GitHub Pages 必须使用 `npm run deploy` 或 `npm run build:github-pages` 生成的产物

### 图片不显示

- 新增图片时，优先放到 `public` 目录
- 代码里不要手写以站点根目录开头的绝对路径，保持走现有的 `withBasePath()`

### 页面改了但线上没更新

- 先确认本地执行过 `npm run deploy`
- 再确认部署命令执行过程中没有报错
- GitHub Pages 可能有 1-3 分钟缓存，稍等后强刷页面再看
